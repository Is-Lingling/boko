## 修复：博客前端跨设备不显示文章（静态数据优先 bug）

- **现象**：后端 `/api/articles` 正常返回全量数据，但页面只显示本地 localStorage 的少量文章，换设备/清缓存后看不到任何文章。
- **根因**（实际代码，非用户描述的简化版本）：`js/main.js` 的 `loadPrimaryData(view)` 仅在非 home/space 视图才调用 `loadArticlesFromFile()`（该函数内部调用 `Api.listArticles()` 拉取后端）。`home` 是默认落地页，它从不请求 API，只依赖 per-device 的 `localStorage['articlesData']` 缓存（`STORAGE_KEYS.articles = 'articlesData'`，`defaultArticles = []`）。所以新设备/清缓存后 home 永远为空、且无法跨设备同步。
- **死代码**：`js/index.js` 是旧的"静态 JSON + localStorage"实现（`fetch('articles.json')` + 合并 `articlesData`），但 `index.html` 未引用它，属遗留死代码。用户的排查描述与该文件高度吻合，但运行路径走的是 `main.js/data.js` 这套 API 驱动代码。
- **修复**：在 `loadPrimaryData` 中，对所有视图（含 home）统一先 `loadArticlesFromFile().then(refreshArticleUi)`，以 API 为唯一数据源；`loadArticlesFromCache()` 仅作首屏快渲染 + 离线兜底（data.js 的 loadArticlesFromFile 失败时会回退到缓存）。已 `node --check` 通过。
- **后续**：需重新构建/部署容器使修改生效；`index.js` 建议删除以免混淆。

## 顶栏/左右侧栏未钉在视口（随页面滚走）根因与修复

- **现象**：用户要求顶栏与左右侧边栏固定在视口、不随页面滚动，只有中间区滚动。代码本身已对 `.top`/`.box1`/`.box3` 设 `position:sticky`，但实测它们仍随页面滚走。
- **根因（数值诊断确认）**：`css/responsive.css` 根规则 `html,body{overflow-x:hidden}`。按 CSS 规范，`overflow-x:hidden` 会把另一轴 `overflow-y` 强制计算为 `auto`，于是 `body` 变成了滚动容器（computed `overflow-y:auto`）。而实际滚动发生在 `documentElement`(html) 上；`position:sticky` 的“最近滚动容器”落到了**不滚动的 body**，导致 sticky 失效、栏随页面滚走。
- **修复**：将根规则改为 `overflow-x: clip`。`clip` 只裁剪横向溢出、**不创建滚动容器**，因此 `body` 的 `overflow-y` 保持 `visible`，视口(html)成为唯一滚动容器，`sticky` 正确绑定视口 → 顶栏(top:6px)与左右栏(top:calc(64px+gap))钉在视口，中间区随页面滚动。
- **验证**：无头 Chrome 计算样式对比——`hidden` 时 `bodyOverflowY=auto`（bug），`clip` 时 `bodyOverflowY=visible`（修复）；文档仍可纵向滚动(docScrollH 5293 > innerH 813)。注：无头 `--dump-dom` 模式不提交程序化 scrollTo，无法观察实际滚动像素，但滚动容器机制已用计算样式坐实。横向溢出防护由 clip 继续提供。
- 仅改 `responsive.css` 一行根规则，未动 index.css(210KB)/article-unified.css，亦未改动依赖 window.scrollY 的绳索/TOC 滚动监听（window 仍是滚动者，逻辑照常）。
- **修订（同回合）**：首版用 `overflow-x:clip`，用户反馈文章详情页右侧栏(.box3)在真实浏览器消失（clip 对 sticky 子元素有裁剪怪象，无头 Chrome 不复现）。改为**仅 `html` 设 `overflow-x:hidden`、`body` 不设 overflow(保持 visible)** —— 仍避免 body 成滚动容器、sticky 绑定 html/viewport；横向溢出由 html 裁剪兜底，且消除 clip 风险。再验证：`htmlOverflowX=hidden/htmlOverflowY=auto`、`bodyOverflowX=visible/bodyOverflowY=visible`；详情页 `box3=block`、三卡 VISIBLE、网格 `230px 708px 290px`。两目标同时达成，且不影响 .box3 仅 view-detail 显示的逻辑。

- 用户明确要求：`#sidebarCommentsList`(留言)、`#statArticles`(站点统计)、`#hotList`(热门文章排行) 三张卡片**只能出现在文章详情页右侧，其他页面不显示**。
- 三张卡片容器均只存在于全局 `.box3` 内（index.html:616–645），无其它渲染位置 → 只要 `.box3` 仅在 `view-detail` 显示，需求即满足。上一轮 `.box3` 仅 `view-detail` 显隐的修法已覆盖此需求。
- **数值验证（无头 Chrome，真实 CSS，注入 articles 后依次切视图）**：
  - 桌面 1280px：`detail` → box3=block，三卡 VISIBLE；`home`/`list` → box3=none，三卡 hidden。
  - 平板 900px：`detail` → box3=block，三卡 VISIBLE；`home`/`list` → box3=none，三卡 hidden（`body.view-detail .box3{display:block!important}`(0,2,0) 压过平板块 `.box3{display:none!important}`(0,1,0)）。
  - 移动 <768px：`.box1,.box3{display:none!important}` 全盘隐藏（单栏设计，无右侧栏）→ 无泄漏，符合"其他页面不显示"。
